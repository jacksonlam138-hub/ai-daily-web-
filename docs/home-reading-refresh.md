# 首页阅读优化

## 意图

保留既有数据源与角色分析架构。首页先回答“有什么值得读”，再按用户选择提供角色建议；不增加新闻数量、生成凑数文案或启动自动采集。

原页面的首条标题在 1440px 桌面视口约 429px 处才出现，右侧分类重复、来源为“其他”，读完缺少下一期入口。

## 本轮变化

- 压缩页头和工具栏，缩短正文行宽。保留 PingFang SC 和整卡打开原文。
- 新访客默认“只看新闻”，已有角色偏好仍从本地读取。建议继续按编号分项展示，移除大面积灰色底块。
- 没有对应角色建议时，仅在工具栏说明一次，不用别的角色建议填充。
- 无明确来源名称时，使用原文域名；不展示完整查询参数，也不推断机构身份。
- 右侧改为最近三期较早日报的日期与头条入口；小屏移到正文后。往期页同样只推荐比当前期更早的内容，不混为本期新闻。
- 采集来源和 AI 解读说明保留在页脚，AIHOT 的来源与时间窗口仍明确标注。

## 验证

- `pnpm test`：来源显示、分项解析、缺省角色、双信号源隔离等回归。
- `pnpm exec tsc --noEmit` 与改动文件 ESLint 检查。
- 全仓 ESLint 的既有阻塞：退订页 `react-hooks/set-state-in-effect`、数据文件 `prefer-const`；不属于此次改动，不将全仓检查报告为通过。
- `pnpm build`：使用仅包含本轮改动和既有已发布数据的干净快照。
- 浏览器打开待验环境后运行 `playwright-cli run-code --filename=tests/browser-reading.cjs`。该脚本使用当前 2026-09-22 期（有产品解读、无设计解读）验证默认视图、偏好记忆、空角色状态、分项、原文链接、往期、搜索与键盘焦点；日期换版后应相应更新测试内容条件。
- 1440 / 768 / 390 / 360px 检查正文及解读无横向溢出、小屏往期顺序、苹方字体优先级。

## 发布边界

原工作区存在未提交的日报草稿与自动采集工作流。本次不修改或发布它们；发布包从暂存树/已提交版本导出，避免新增往期入口将本地草稿一起暴露。
这次调整不修复自动日更，不代表新闻来源覆盖率已经改善。
